HRV is not a number from the pulse wave. It is the rhythm between beats.

For a PulseSensor-on-CYD display, the valuable data is a stack: live waveform for trust, beat event for timing, IBI history for variability, then one or two slow-changing HRV summaries.

Measurement Pipeline

Keep the mental model explicit on the display: raw light reading becomes a detected beat; beat-to-beat intervals become HRV. The CYD should show just enough of each layer that the user can tell whether the HRV number is believable.

1. Sample
Read analog PPG around 500 Hz. This is your debug truth.
2. Detect
Threshold/adaptive detection marks the start of each pulse.
3. Time
IBI is the milliseconds between consecutive beats.
4. Window
Store 30-120 clean IBIs. Reject dropouts before summarizing.
5. Track
Show RMSSD/SDNN trends, not medical conclusions.

Best First Build

Build one “session” screen that layers trust plus HRV. Make the main number BPM, because people understand it instantly. Make RMSSD the secondary number, because it is easy to compute from short-term IBI differences and responds to breathing. Make signal quality impossible to miss.

Show raw signal continuously.

If the waveform is noisy, the HRV metric should visually lose confidence instead of pretending to be precise.

Use IBI windows.

Track a rolling buffer of clean intervals. Compute HRV only after enough accepted beats, then update slowly.

Store sessions, not every sample.

MicroSD can keep timestamped summaries: duration, average BPM, RMSSD, SDNN, rejected beat count, and notes.

Useful Computations

IBI[n] = beatTime[n] - beatTime[n-1]
BPM_instant = 60000 / IBI[n]
RMSSD = sqrt(mean((IBI[n] - IBI[n-1])^2))
SDNN = standardDeviation(IBI window)
signalQuality = stable amplitude + plausible IBI + low dropout count
